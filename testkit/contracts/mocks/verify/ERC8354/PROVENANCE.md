# Provenance: vendored ERC-8354 verifier and fixture proof

Four files in this directory are vendored, not written here. They are copied
byte for byte, with no edits at all, so the claim is checkable by hash rather
than taken on trust.

## Source

Reference implementation, the one `agent-ercs/contracts/verify/ERC8354/README.md`
names:

    repo:   https://github.com/zexoverz/confidential-agent-policy-verdicts
    commit: 948e090c09dd5ec1d4593013303bc5260ef7c466
    licence: CC0-1.0

`HonkVerifier.sol` is generated by Barretenberg (`bb`) from that repo's Noir
allowlist circuit. `allowlist.proof` and `allowlist.public_inputs` are that
repo's committed fixtures for the same circuit. Regenerating the verifier
without regenerating the proof, or the reverse, breaks `ConsumeReal.t.sol`.

## Verify

That table is the only place any of this is written down. `scripts/check-provenance.sh`
reads the repo, the commit, and the hashes straight out of it, so there is no
second copy to keep in sync and nothing that can quietly disagree with what CI
enforces.

From the repo root, offline, checking the files as they sit in this tree:

```sh
./scripts/check-provenance.sh
```

`scripts/run-all-tests.sh` runs exactly that on every CI run and fails the build
on a mismatch, so a regenerated verifier or a swapped fixture cannot slip past
while `ConsumeReal.t.sol` stays green against a different artifact.

To confirm those hashes really are the upstream files, and not just hashes of
whatever happens to sit here, fetch the source and hash it independently:

```sh
./scripts/check-provenance.sh --upstream
```

That fetches each upstream path at the pinned commit and hashes it against the
same table. It is deliberately not part of the CI run, so a green build never
depends on `raw.githubusercontent.com` being reachable.

## Interfaces

The interfaces these compile against are the merged spec, not this mirror.
`ethereum/ERCs#1919` merged at `9ddae72d666c22a923e78fb923844d1e0494bf1f`, and
its `assets/erc-8354/src` copies of `IConfidentialPolicyVerdict.sol`,
`IPolicyDomainRegistry.sol`, `IIdentityRegistry.sol`, `IVerifier.sol`,
`IPolicyAttestation.sol`, and `PolicyAction.sol` are byte identical to the
same files in the reference repo above.
