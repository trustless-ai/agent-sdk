# invinoveritas ReviewGateClient (TypeScript)

**Recompute-to-verify: YES (the proof, not the verdict itself).**

A pre-action judgment gate: before an agent takes an irreversible action, `ReviewGateClient.review()` calls [invinoveritas](https://api.babyblueviper.com)'s `/review` endpoint and returns a verdict — `approve`, `reject`, or `approve_with_concerns` — plus a signed proof. The judgment call itself (was this a sound thing to do?) is not something a third party recomputes from public data; that would defeat the point of asking an independent party for a second opinion. What *is* independently verifiable is that the verdict returned is exactly the one invinoveritas issued, untampered, at the stated time — a `verifyLocal()` call recomputes that from the signed bytes alone, checked against invinoveritas's published key. No trust in this client, and no trust in invinoveritas's own infrastructure past the one public key, is required for that half.

## Why this module isn't under an ERC number

Every other module in this SDK lives at `<category>/<ERCXXXX>` and is generated by the `/add-erc` skill from a Solidity interface defined in the `agent-ercs` submodule. `/review` doesn't have an on-chain counterpart — it's a plain off-chain HTTP judgment service, not a contract — so there's no interface for `/add-erc` to read and no ERC number to file this under. This module is hand-written for that reason, not because it skipped the generation step. If invinoveritas's verdict format is ever formalized as an on-chain-anchored ERC (a real candidate: binding a `decision_ref` to an on-chain event so a verdict's existence-before-action is itself checkable from chain state, not just the signature), this module should be reconsidered against that ERC's own generated client rather than kept as a permanent hand-written exception.

## Usage

```ts
import { ReviewGateClient } from '@trustless-ai/agent-sdk/governance/InvinoVeritas'

const gate = new ReviewGateClient({ apiKey: process.env.INVINOVERITAS_API_KEY! })

const result = await gate.review('rm -rf /var/log/nginx/*.log', {
  artifactType: 'shell_command',
})

if (result.verdict === 'reject') {
  // Don't just trust the string — confirm the proof is real before acting on it.
  const check = gate.verifyLocal(result)
  if (check.valid) {
    console.log('Confirmed, untampered reject:', result.summary)
  }
}
```

## API

- **`new ReviewGateClient({ apiKey, baseUrl? })`** — `baseUrl` defaults to `https://api.babyblueviper.com`; override it to point at a self-hosted or staging deployment of the same API surface.
- **`review(artifact, options?)`** — POSTs `{ artifact, artifact_type?, context?, sign }` to `/review` (`sign` defaults to `true` — the whole reason to route through this client instead of an unsigned internal heuristic is to get something checkable, not another thing to trust). Returns `{ verdict, confidence, summary, issues[], proof? }`.
- **`verifyLocal(response)`** — pure, offline recompute of `response.proof.event`'s signature via [`invinoveritas-verify`](https://www.npmjs.com/package/invinoveritas-verify) (the same package invinoveritas publishes for anyone, not SDK-internal-only code). Throws if `response` has no `proof.event` (i.e. `review()` was called with `sign: false`).
- **`confirmReplyAnchored({ rpcUrl, address }, replyHash)`** — closes a real gap `review()`/`verifyLocal()` leave open: they prove what invinoveritas *said* about a proposed action, not that the agent's downstream on-chain reply actually reached an ERC-8301 `IAgentWorkflow` gate rather than being silently dropped before submission. Reads `getAgentReply(replyHash)` on the given workflow contract (read-only, no wallet needed) and returns `{ anchored: false }` if the hash was never anchored, or `{ anchored: true, proven, verifier, verificationDigest }` if it was. A genuine RPC/network failure is NOT swallowed into `anchored: false` — it throws, so "couldn't check" is never mistaken for "confirmed not anchored". See the method's own doc comment for a naming note: an earlier ERC-8301 draft apparently named this primitive's event `AgentReplyAnchored`; the version merged into `trustless-ai/agent-ercs` doesn't carry that event name, so this reads the `getAgentReply` view function's revert-vs-return behavior directly instead of depending on it.

## Layer 2 — what `verifyLocal` actually checks

`verifyLocal` delegates to `invinoveritas-verify`'s `verifyProofLocal`, which checks, entirely offline:

1. **`id_integrity`** — recomputes the NIP-01 event id (`sha256(JSON.stringify([0, pubkey, created_at, kind, tags, content]))`) and confirms it matches the claimed `id`.
2. **`signature_valid`** — BIP-340 Schnorr-verifies `sig` over `id` against `pubkey`.
3. **`issued_by_invinoveritas`** — confirms `pubkey` matches invinoveritas's published verifier key.
4. **`is_proof_event`** — confirms the event's `kind`/`content.schema` match invinoveritas's proof format, so an unrelated but validly-signed Nostr event can't be mistaken for a verdict proof.

No RPC call, no deployed contract, no dependency on invinoveritas's servers being reachable at verification time — the same shape of guarantee the rest of this SDK's `verify()` methods provide for on-chain EIP-712 signatures, applied to an off-chain signed judgment instead.
